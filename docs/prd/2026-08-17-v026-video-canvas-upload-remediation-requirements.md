# v0.0.26 视频、画布与上传修复需求

## 1. 背景

v0.0.25 上线后，视频路由配置、浏览器直传对象存储和创意画布暴露出配置语义重复、运行时可见性不一致及关键交互不可用等问题。本期统一修复这些问题，并补齐画布图片框、图片多结果和自动估价能力。

## 2. 目标

1. 视频路由能力只由真实账号、真实模型和路由候选关系决定，不再人工维护一份用户可见参数组合。
2. 所有路由模型的按分组可见配置可正确保存、回显并在运行时生效。
3. R2/S3 浏览器直传受 CORS 或网络阻断时，上传可自动降级并给出明确错误。
4. 画布节点可调整尺寸，节点内部交互控件可正常使用。
5. 画布图片生成支持自动估价、平台级多结果生成、图片输入框和可恢复的结果布局。

## 3. 范围

### 3.1 视频能力配置

1. 删除后台视频路由配置中的“用户可见参数组合”。
2. 删除对应管理 API 请求、响应和持久化依赖。
3. 历史 `visible_options.combinations` 数据允许保留但不再读取；管理员不需要迁移数据。
4. 视频能力列表根据路由绑定的可用候选真实模型能力计算完整参数组合并去重。
5. 候选必须满足：账号启用、真实模型启用、能力启用且验证通过、路由候选启用。
6. 报价和创建任务必须再次按完整组合校验。能力列表过期或当前没有候选支持时，返回字段级能力不匹配错误。
7. 用户端只展示至少被一个候选完整支持的组合；服务端仍是最终权威。

### 3.2 路由模型分组可见性

1. 后台路由模型列表和详情必须回传已关联的 `group_ids`。
2. 创建、编辑后重新打开表单时，已选分组必须正确回显。
3. 图片、视频、音频和文本路由共用同一套回显逻辑，不允许只修视频页面。
4. 视频能力、视频报价、视频任务创建和画布视频生成必须携带当前用户全部有效用户组。
5. 可见性规则：`public` 对所有已登录用户可见；`groups` 仅对命中至少一个启用用户组的用户可见；`hidden` 对所有普通用户不可见。
6. 不可见路由不得通过直接填写路由代码绕过能力列表。

### 3.3 浏览器上传可靠性

1. S3/R2 仍优先使用预签名 URL 浏览器直传，保留 SHA-256 分片校验和 `ETag` 完成语义。
2. 直传因 CORS、网络异常或浏览器 `fetch` 失败时，当前上传会话自动切换到同源 API 分片上传。
3. 降级后剩余分片直接使用同源 API，不重复触发已知失败的跨域预检。
4. API 必须流式转发分片到对象存储，不得把 1 GiB 文件整体读入内存；现有分片大小、并发、暂停和恢复能力保持不变。
5. 服务端必须校验声明大小和 SHA-256，返回真实 `ETag`。
6. 两条链路都失败时，任务列表展示分片编号、可理解的错误原因和重试入口，不显示孤立的 `Failed to fetch`。
7. 存储探测或配置界面提示浏览器直传所需规则：允许目标前端 Origin、`PUT`，并暴露 `ETag`；不得要求 R2 不支持的可选 UploadPart 校验头。

### 3.4 画布节点尺寸与事件

1. 桌面端和平板横屏完整编辑模式下，所有节点支持拖拽调整宽高。
2. 节点按类型设置最小宽高；不设置业务性最大尺寸。
3. 缩放结果保存到现有 `node.size`，支持撤销、重做、自动保存、画布预览、小地图和自动整理。
4. 按钮、输入框、选择器、媒体控件、滚动区域和缩放手柄不得触发节点拖动。
5. 节点标题栏和非交互空白区域用于拖动。
6. 提示词节点的变量、资源、优化按钮必须可点击；生成节点的费用、生成、取消和恢复按钮必须可点击。

### 3.5 画布图片生成

1. 图片生成节点不再显示“查看费用”。输入完整后自动估价，并直接展示预计积分和“确认生成”。
2. 参数、提示词、变量、输入资产、连线或模型发生变化时，旧估价立即失效并在约 300ms 防抖后重新估价。
3. 输入不完整时不请求估价，节点显示具体缺失项；能力不匹配时显示对应字段错误。
4. 点击确认生成前先保存画布，并确认估价对应的文档签名仍有效；不一致时重新估价。
5. 视频生成节点本期保留现有显式报价流程，但其内部按钮恢复正常点击。
6. 图片生成数量与创作页一致，允许平台任务数量大于真实模型单次 `n`。后端沿用现有拆分并发逻辑，不修改单次真实模型上限。

### 3.6 图片框

1. 复用现有 `image` 节点作为图片框，不新增节点类型和 Schema 版本。
2. 工具栏和节点菜单可新建空图片框。
3. 空图片框可以从当前项目资产库选择图片，也可以上传一张本地图片。
4. 本地上传必须进入统一资产库并标记为本地上传；上传完成且画布仍打开时，自动填入发起上传的图片框。
5. 图片框绑定资产后使用统一媒体访问接口加载缩略图或预览图，不保存签名 URL。
6. 图片框可连接到图片生成节点作为 `reference` 输入。
7. 空图片框可连接到图片生成节点作为 `result` 输出；已绑定资产且不是该生成链路历史输出的图片框不能新建输出连接。
8. 空图片框只有在存在合法的图片生成 `result` 入边时才允许保存。

### 3.7 提示词资源候选

1. 图片框和提示词节点共同汇入同一个图片生成节点时，该图片框自动成为提示词“资源”按钮的候选。
2. 候选展示资产缩略图和资产名称；用户选择后在当前光标位置插入 `{{@资产名称}}`。
3. 连线不得自动改写提示词。
4. 同名资源绑定继续由生成节点和后端解析器权威校验；无同名资产时显示未关联错误。

### 3.8 多结果归位

1. 图片任务第一次成功时，按连线顺序优先填充预连接的空图片框。
2. 结果数量超过空框数量时，服务端在生成节点右侧自动创建剩余图片节点并连接 `result` 边。
3. 同一图片生成节点后续再次执行时，始终为本次全部结果新增图片节点，不覆盖或清空历史节点。
4. 结果节点按运行批次分组排列，并保留到生成节点的结果连接。
5. 归位按运行 ID 和资产 ID 幂等；刷新、轮询、重复恢复不得重复创建或重复填充。
6. 生成成功但保存画布冲突时，运行进入可恢复状态，不重新生成和扣费。

## 4. 非目标

1. 不调整视频生成节点的报价产品交互。
2. 不改动图片任务的现有多并发拆分架构。
3. 不自动修改 R2 Bucket CORS，不要求对象存储凭据具备 Bucket 管理权限。
4. 不新增独立 `image_frame` 节点类型，不升级画布 Schema。
5. 不覆盖或删除历史生成资产。

## 5. 验收标准

1. 视频路由表单不再出现用户可见参数组合，用户端参数来自真实候选能力。
2. 任意媒体类型路由按分组保存后可正确回显；视频组内用户可见、组外用户不可见。
3. 模拟跨域直传失败后，上传自动经 API 完成，任务列表给出降级状态而非 `Failed to fetch`。
4. 所有画布节点可调整大小，节点内部按钮和表单不会拖动节点。
5. 图片生成节点自动展示预计积分，并可直接确认生成。
6. 画布图片数量可以设置为大于 1，生成一个平台任务并产生相应数量结果。
7. 空图片框可选资产、可上传、可作参考输入和结果输出。
8. 首次多结果优先填空框并补建不足节点；第二次生成完整追加一组结果。
9. 提示词资源按钮列出相关图片框并在光标处插入资源占位符。
10. 桌面端和平板横屏完成端到端功能验收，全量验证、API smoke 和代码审查通过。
