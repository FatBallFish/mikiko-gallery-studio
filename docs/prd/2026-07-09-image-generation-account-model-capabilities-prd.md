# 图片生成平台账号与模型能力配置改造需求文档

## 1. 背景

当前图片生成平台接入了多种上游图片生成接口，例如通过 GPT / Codex 反代得到的生图接口，以及 Adobe 等平台反代得到的生图接口。

在近期测试中发现，不同上游账号、不同模型自身支持的图片生成参数和能力并不一致。例如：

* GPT / Codex 类型接口：

  * 通常只支持 1K、2K；
  * 支持的图片比例较固定；
  * 部分传入的像素参数可能不会生效，需要排查。
* Adobe 类型接口：

  * 可能支持 1K、2K、4K；
  * 可能支持自定义像素比例；
  * 支持能力更丰富。

因此，需要对后台账号及模型配置能力进行扩展，使平台能够准确配置每个模型支持的生图能力，并在用户前端根据当前路由模型下所有可用账号/模型能力进行展示、校验和费用预估。

## 2. 目标

本次需求主要改造图片生成平台的创作功能相关配置与生成逻辑，目标如下：

1. 在管理后台增加模型级别的图片生成能力配置。
2. 支持配置模型允许的最大参考图片数量。
3. 支持配置模型的图片尺寸能力：

   * 支持按图片比例生成；
   * 支持按指定像素大小生成；
   * 支持两者同时存在。
4. 用户前端展示当前路由模型下所有账号/模型支持能力的合集，即取能力并集。
5. 用户选择参数后，后端需要判断是否存在可支持该配置的账号/模型。
6. 用户选择参数后，后端需要预估本次生成预计消耗的积分。
7. 如果用户选择的参数没有任何账号/模型支持，前端需要提示当前配置暂不支持生成。
8. 调整生成执行逻辑，区分“比例 + 清晰度”和“指定像素大小”两种模式。
9. 排查 Codex 类型接口中像素参数传入后不生效的问题，并根据结果调整适配逻辑。

## 3. 涉及系统范围

本次改造涉及以下模块：

1. 用户端前端
   图片生成创作页面参数选择交互。

2. 管理后台前端
   接入账号菜单及模型参数配置页面。

3. 管控后端
   账号、模型配置保存、查询、能力聚合、参数校验、积分预估。

4. 图片生成 Worker 后端
   实际生成任务执行、参数转换、调用上游接口。

## 4. 当前配置现状

### 4.1 管理后台账号配置现状

当前管理后台“接入账号”菜单下，账号配置项主要包括：

* 账号名称
* 接入方式
* 鉴权方式
* 基础路由
* 密钥状态
* OpenAI 类型下的接口来源，例如 Codex 或 API
* 优先级
* 权重
* 并发限制
* 超时毫秒
* 其他基础配置

### 4.2 当前模型参数配置现状

账号下的模型参数目前包括：

* 模型代码，即真实模型名称
* 展示名称
* 适配任务类型：

  * 文生图
  * 参考生图
  * 图片编辑
* 图片质量列表
* 单图成本
* 币种

## 5. 新增配置项

### 5.1 最大参考图片数量

该配置应加在“账号下对应的模型参数”维度，而不是账号维度。

原因是同一个账号下不同模型可能支持不同数量的参考图片。

新增字段：

* 字段名称：最大参考图片数量
* 配置位置：账号下的模型配置
* 字段含义：该模型在参考生图或图片编辑场景下，允许用户最多上传/传入的参考图片数量
* 默认值：5
* 示例值：

  * 3
  * 5
  * 16

要求：

* 后台模型配置表单中增加该字段。
* 用户前端上传参考图时，需要根据当前可用模型能力限制最大数量。
* 后端提交生成任务时，也需要校验参考图数量是否超过支持范围。

### 5.2 图片尺寸支持类型

在模型配置中新增“尺寸支持类型”配置，用于描述模型支持哪种图片尺寸输入方式。

支持类型包括：

1. 图片比例
2. 像素大小
3. 图片比例 + 像素大小

后台表单要求：

* 提供勾选项：

  * 支持图片比例
  * 支持像素大小
* 两个选项可以同时勾选。
* 至少需要勾选一个。

### 5.3 支持的图片比例列表

当模型勾选“支持图片比例”时，后台需要展示比例配置项。

默认比例建议包括：

* 1:1
* 16:9
* 9:16
* 4:3
* 3:4

要求：

* 支持多选。
* 支持手动新增自定义比例。
* 比例配置需要跟随模型保存。
* 用户端展示时，需要聚合当前路由模型下所有可用账号/模型支持的比例合集。

### 5.4 支持的像素大小列表

当模型勾选“支持像素大小”时，后台需要展示像素大小配置项。

默认预设：

* 1024×1024

后续可继续扩展其他预设，例如 2K、4K 或其他自定义尺寸。

要求：

* 支持后台手动添加像素大小。
* 像素大小需要跟随模型保存。
* 用户端展示时，需要聚合当前路由模型下所有可用账号/模型支持的像素大小合集。

### 5.5 清晰度选项

当前已有“图片质量列表”，本次可以复用该配置作为清晰度选项。

逻辑调整：

* 只有当用户选择“图片比例”模式时，才展示清晰度选项。
* 当用户选择“指定像素大小”模式时，不展示清晰度选项。
* 因为清晰度主要用于结合比例计算最终像素值，而指定像素大小已经有明确尺寸，不需要再通过清晰度换算。

## 6. 用户端前端交互需求

### 6.1 能力展示逻辑

用户进入图片生成页面后，前端展示的参数选项应基于当前路由模型下所有可用账号/模型能力的合集。

例如：

* 账号 A 支持比例：1:1、16:9
* 账号 B 支持比例：9:16、4:3
* 用户端展示比例合集：1:1、16:9、9:16、4:3

像素大小、清晰度、最大参考图片数量等也需要按照类似逻辑处理。

### 6.2 新增尺寸选择模式

用户端图片生成页面需要增加尺寸选择模式切换。

模式包括：

1. 按比例生成
2. 按指定像素生成

当用户选择“按比例生成”时：

* 展示图片比例选项。
* 展示清晰度选项。
* 需要提示或展示当前比例 + 清晰度预计生成的像素大小。
* 后端仍按照原有逻辑，根据比例和清晰度换算最终像素值。

当用户选择“按指定像素生成”时：

* 展示像素大小选项。
* 不展示清晰度选项。
* 用户选择的像素值即为最终生成尺寸。
* 后端调用时直接传递该像素大小，不再基于清晰度进行换算。

### 6.3 不支持配置提示

用户选择参数后，前端需要根据后端判断结果展示是否支持生成。

如果没有任何账号/模型支持当前配置，需要在页面提示：

“当前配置暂不支持生成，请更换类似配置。”

该状态下应禁止发起生成，或在点击生成时进行强校验并阻断。

### 6.4 积分预估展示

用户选择生成参数后，后端需要返回预计消耗积分。

前端需要展示预计积分消耗。

积分预估需要考虑：

* 当前选择的模型路由
* 任务类型
* 图片数量
* 图片比例或像素大小
* 清晰度
* 单图成本
* 币种/积分换算规则
* 实际可支持该配置的账号/模型

## 7. 后端能力匹配逻辑

### 7.1 能力并集

后端需要提供接口，返回当前路由模型下所有账号/模型支持能力的合集。

需要聚合的能力包括：

* 支持的任务类型
* 最大参考图片数量
* 支持的图片比例列表
* 支持的像素大小列表
* 支持的清晰度列表
* 其他后续可能扩展的模型能力

### 7.2 配置支持性校验

当用户选择生成参数后，后端需要判断是否存在至少一个账号/模型支持该配置。

校验维度包括：

* 任务类型是否支持
* 参考图片数量是否小于等于模型最大参考图片数量
* 尺寸模式是否支持
* 如果是比例模式：

  * 图片比例是否支持
  * 清晰度是否支持
* 如果是像素模式：

  * 像素大小是否支持
* 其他模型调用限制

如果存在至少一个账号/模型支持，则返回可生成状态。

如果没有账号/模型支持，则返回不可生成状态及提示文案。

### 7.3 路由筛选逻辑

生成任务真正执行时，不能只基于路由模型随机选择账号，而是需要在路由候选账号/模型中进一步筛选出支持当前参数配置的账号/模型。

筛选完成后，再按照现有的优先级、权重、并发限制、超时等规则进行调度。

## 8. 图片生成 Worker 后端逻辑

### 8.1 比例模式

当用户选择“图片比例”模式时：

* 保持现有逻辑。
* 后端根据图片比例 + 清晰度计算最终像素大小。
* 再将计算后的像素值传递给上游接口。
* 但需要结合 Codex 类型接口参数不生效问题的排查结果做适配。

### 8.2 像素模式

当用户选择“指定像素大小”模式时：

* 不再使用清晰度。
* 不再根据比例和清晰度换算像素。
* 直接将用户选择的像素大小传递给上游接口。
* 调用前需要确保被选中的账号/模型支持该像素大小。

### 8.3 Codex 类型接口问题排查

当前观察到 Codex 类型接口传入像素值后似乎不生效，可能存在：

* 上游接口不支持该参数；
* 参数字段名或格式不正确；
* 后端转换逻辑不符合接口要求；
* 上游实际只支持固定 1K 或固定比例；
* 参数被中间层或反代层忽略。

需要排查：

1. 当前 Worker 传给 Codex 类型接口的实际请求参数。
2. Codex 类型接口支持的尺寸参数格式。
3. 传入不同尺寸参数时，上游返回图片尺寸是否变化。
4. 是否需要对 Codex 类型接口单独做参数适配。
5. 如果接口本身不支持某些尺寸，应在模型配置中准确限制，而不是让用户端继续展示不可用能力。

## 9. 数据结构建议

### 9.1 模型配置新增字段

建议在模型配置中新增以下字段：

```json
{
  "max_reference_image_count": 5,
  "size_modes": ["ratio", "pixel"],
  "supported_ratios": ["1:1", "16:9", "9:16", "4:3", "3:4"],
  "supported_pixel_sizes": ["1024x1024"]
}
```

字段说明：

* `max_reference_image_count`：最大参考图片数量
* `size_modes`：支持的尺寸模式

  * `ratio`：图片比例
  * `pixel`：像素大小
* `supported_ratios`：支持的图片比例列表
* `supported_pixel_sizes`：支持的像素大小列表

### 9.2 用户生成请求参数建议

比例模式：

```json
{
  "size_mode": "ratio",
  "ratio": "1:1",
  "quality": "1K"
}
```

像素模式：

```json
{
  "size_mode": "pixel",
  "pixel_size": "1024x1024"
}
```

## 10. 验收标准

### 10.1 管理后台

* 模型配置中可以配置最大参考图片数量。
* 模型配置中可以勾选支持图片比例、支持像素大小。
* 勾选图片比例后，可以配置比例列表。
* 勾选像素大小后，可以配置像素大小列表。
* 默认最大参考图片数量为 5。
* 默认像素大小至少包含 1024×1024。
* 配置保存后，用户端和后端校验能正确读取。

### 10.2 用户前端

* 用户可以选择按比例生成或按像素生成。
* 按比例生成时展示比例和清晰度。
* 按像素生成时展示像素大小，不展示清晰度。
* 按比例生成时可以展示预计生成像素大小。
* 当前配置无账号/模型支持时，提示“当前配置暂不支持生成，请更换类似配置。”
* 当前配置可支持时，可以展示预计消耗积分。

### 10.3 后端

* 能正确返回当前路由模型下的能力合集。
* 能根据用户选择参数判断是否存在可支持账号/模型。
* 能根据参数预估积分消耗。
* 生成任务执行前能筛选出真正支持当前配置的账号/模型。
* 不支持的配置不会被错误提交到 Worker 执行。

### 10.4 Worker

* 比例模式下保持原有比例 + 清晰度换算逻辑。
* 像素模式下直接传递像素大小。
* Codex 类型接口尺寸参数不生效问题完成排查。
* 根据排查结果完成必要适配或配置限制。

## 11. 本期不做范围

本期主要改造图片生成尺寸能力配置与路由校验逻辑，暂不包含：

* 新增更多默认像素尺寸，除 1024×1024 外可后续补充。
* 大规模重构现有路由策略。
* 新增新的上游账号类型。
* 修改积分体系本身。
* 修改非图片生成相关功能。

## 12. 待确认问题

以下内容需要后续进一步确认：

1. 默认像素大小列表除 1024×1024 外，还需要内置哪些尺寸。
2. 清晰度列表是否完全复用现有图片质量列表，还是需要单独命名。
3. 积分预估公式是否已有统一实现，还是需要本次新增。
4. 不同上游接口的尺寸参数字段是否需要分别配置映射。
5. Codex 类型接口实际支持的尺寸能力，需要排查后确定。
6. 图片比例转像素的现有规则是否需要保留全部兼容。
7. 如果多个账号都支持同一配置，积分预估应按最低成本、默认路由成本，还是最终路由命中账号成本计算。
