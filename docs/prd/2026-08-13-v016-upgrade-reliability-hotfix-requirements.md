# v0.0.16 升级可靠性热修需求

> 日期：2026-08-13
> 状态：已确认
> 线上基线：应用 v0.0.12，mgsctl v0.0.15
> 目标版本：v0.0.16

## 背景

线上环境从 v0.0.12 升级 v0.0.15 时，目标版本数据库迁移在为历史
`model_accounts` 增加非空 `public_id` 字段时失败：历史行无法获得 Ent 的 Go
侧 UUID 默认值。升级器在服务滚动前停止并恢复旧 runtime，因此线上 v0.0.12
容器保持健康，数据库迁移事务也未留下 `public_id` 半成品列。

同一次操作中，mgsctl 自升级曾因下载 GitHub Release 资产超过固定两分钟总超时而
失败。现有错误把校验文件和二进制下载都折叠为“release artifact unavailable”，且
下载过程中没有进度反馈。

## 目标

1. 任意带有历史 `model_accounts` 数据的受支持 PostgreSQL 数据库均可幂等升级，
   每个账号获得稳定、唯一、非空的 `public_id`。
2. 兼容首次迁移、上次迁移留下可空列、部分行已有合法 UUID 三种状态；不得改写
   已有非空 UUID。
3. mgsctl 自升级能容忍 Release 下载的短暂网络故障和慢速链路，并在交互终端展示
   可理解的下载进度。
4. 下载失败错误必须指出阶段、尝试次数和底层原因，且绝不替换当前可执行文件。
5. 发布 v0.0.16 后，在备份线上数据库的前提下完成真实升级验证；任何失败都必须
   保持现有 v0.0.12 服务运行。

## 验收条件

- 迁移前仅含旧字段且至少三行账号数据时，显式迁移成功。
- 迁移后 `public_id` 为 UUID、`NOT NULL`、唯一；历史行均有不同值。
- 重复运行兼容准备和完整迁移不改变已有 `public_id`。
- 自升级 checksum 请求和二进制请求采用独立错误阶段；可重试网络错误最多三次。
- 二进制下载不受两分钟总耗时限制，但连接、响应头和无进展读取仍有边界。
- TTY 下显示已下载字节、总字节、百分比和速率；非 TTY 输出保持简洁且适合脚本。
- SHA-256 校验和原子替换语义保持不变；失败或取消不污染正式二进制。
- 全量 verify、committed review gate、API smoke 和发布 Action 通过。
- 线上升级前生成 PostgreSQL 自定义格式备份并验证备份文件非空。
- 线上应用容器最终全部运行 v0.0.16，健康检查和数据库版本记录均为 v0.0.16。

## 非目标

- 不通过一次性线上 SQL 绕过应用迁移。
- 不修改历史 `public_id` 的公开语义或视频回调 URL。
- 不实现断点续传或多线程下载；mgsctl 资产当前小于 128 MiB，有限重试足够。
- 不在迁移失败后执行逆向数据库迁移。
