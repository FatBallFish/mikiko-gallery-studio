# v0.0.12 体验问题修复与提示词模板需求文档

日期：2026-08-11
状态：关键业务决策已确认，待开发
需求来源：项目负责人对 v0.0.11 线上版本的体验报告、后续明确意见及提示词模板新增需求
实现基线：`origin/main` 提交 `7d6a928`；`v0.0.11` 注解标签对象为 `0b2210a`，解引用后指向同一提交；代码树为 `8bc03f7`
目标版本：`v0.0.12`

## 1. 背景

`v0.0.10` 已交付针对 v0.0.9 体验报告的大部分修复，`v0.0.11` 又补充了部署绑定兼容修复。经过对 `v0.0.11` 的线上使用，仍发现一组正确性和易用性问题。其中最关键的问题是：生成任务与任务产出的每张图片现在允许分别属于不同项目，但部分查询和变更流程仍把任务所属项目当成图片所属项目，导致单独迁移过项目的图片在公开或作为引用时返回 404。

此外，当前版本还存在支付订单超时状态未完整闭环、资产引用无复制逻辑仍受灰度配置限制、管理后台部分字段和操作缺失，以及若干前端交互问题。

本文档定义 `v0.0.12` 相对当前 `v0.0.11` 基线的增量范围。除非本文明确列为回归问题，否则不重新设计 `v0.0.10` 已完成的需求。

## 2. 目标

1. 修复图片当前所属项目与来源任务项目不一致时的查询和操作行为。
2. 所有新的图库资产引用默认且无条件使用“仅创建别名、不复制对象”的方式。
3. 补全可配置、可观测且幂等的支付订单超时生命周期。
4. 用明确、可操作的字段级校验提示替代含糊的生成就绪提示。
5. 补全订单和套餐管理流程，同时保证历史记录不受影响。
6. 优化列表刷新、支付方式展示、创作参数布局和资产批量选择体验。
7. 保持现有生成数量自动拆分、项目、积分钱包、对象清理和历史记录兼容能力不变。
8. 新增支持资源引用、变量、行内校验、安全优化和确定性下游展开的提示词模板能力。

## 3. 术语与归属规则

| 术语 | 定义 |
|---|---|
| 任务所属项目 | `image_tasks.project_id`；决定生成任务在历史任务中归属哪个项目。 |
| 图片所属项目 | `task_images.project_id`；某一张生成资产当前所属的项目，是资产页查询和图片变更操作的权威依据。 |
| 跨项目引用 | 当前创作项目与被引用图片所属项目不同，但图片属于当前用户。此行为允许。 |
| 引用别名 | 指向现有图片对象、不拥有也不复制第二份对象的引用资产记录。 |
| 支付超时 | 从订单创建到未支付订单失效的时间，与到账积分的有效期无关。 |
| 选择模式 | 已加载图片中至少有一张被选中时启用的资产页交互模式。 |
| 提示词模板 | 包含零个或多个资源占位符或变量占位符的原始提示词文本，也是用户在历史记录中看到的提示词。 |
| 资源占位符 | `{{@资源名称}}`；按名称绑定一项已选引用资产。 |
| 变量占位符 | `{{$变量名称}}`；按名称绑定当前草稿中的一个变量值。 |
| 展开后提示词 | 仅供任务运行使用的文本，其中变量已替换为变量值，资源已替换为下游图片位置标识。 |

一个任务可以生成多张图片，每张图片后续都可以迁移到不同项目。迁移其中一张图片绝不能同时迁移任务或同任务的其他图片。

## 4. 范围与优先级

| 优先级 | 范围 |
|---|---|
| P0 | 修复迁移后图片的公开和引用；无条件启用无复制引用别名；补全支付订单超时创建和过期生命周期。 |
| P1 | 自定义尺寸明确报错；后台订单补充用户和积分信息；套餐操作、筛选和排序；支付方式隐私与布局。 |
| P1 | 创作页自动尺寸默认值、模型分组下拉框与最低积分、字段重排、移除限制词。 |
| P1 | 提示词模板解析器和编辑器、引用资产命名、变量表单、安全展开和占位符保护优化。 |
| P2 | 统一列表刷新；提升资产选择对比度；点击选择和桌面拖拽框选。 |

## 5. 功能需求

### 5.1 已迁移图片与跨项目引用

1. 图片详情、公开、取消公开、设置分组、删除、下载和转移操作必须按图片 ID 与当前用户直接查找图片，并使用图片当前的 `project_id`。
2. 任务响应在任务级保留任务所属项目，在每个结果项上独立保留图片当前所属项目。映射任务数据时不得覆盖结果项的项目字段。
3. 图库图片的 `project` 快照必须描述图片所属项目，不能描述任务所属项目。
4. 从图库导入引用图片时，只校验图片存在、未删除且属于当前用户，不校验来源项目与目标项目是否一致。
5. 新版客户端调用 `reference-assets:import-from-gallery` 时不再传 `project_id`。兼容期内服务端继续接受但忽略旧字段。
6. 导入引用图片不得切换全站当前项目；复用来源图片的生成参数时也不得切换当前项目。
7. 迁移一张图片只修改这张图片，不得更新 `image_tasks.project_id` 或同任务其他图片。
8. 批量图片操作可以使用预期来源项目进行乐观并发保护；遇到已变化的图片时，应逐项返回冲突结果，不影响其他图片。

### 5.2 无条件使用无复制引用别名

1. 所有新的图库图片引用只创建引用别名，对对象存储执行零次上传或复制操作。
2. 移除用户可见或后台可配置的 `runtime_rollout/no_copy_reference_aliases` 配置项及其管理接口和界面。
3. 缺少该灰度配置时不得返回 409，也不得阻止引用别名创建。
4. 历史上已复制的引用资产继续可读，并保留 `owns_object=true`；本版本不要求批量转换。
5. `v0.0.10` 已实现的引用对象生命周期保护和最后引用清理检查保持不变。

### 5.3 自定义尺寸校验与默认尺寸模式

1. 自定义像素或比例不合法时，相关控件下方和生成按钮禁用原因中都要展示明确的中文错误。
2. 错误信息必须指出具体违反的规则，例如宽高范围、整数要求、比例格式或不受支持的预设值。
3. `等待参数` 只用于确实缺少必要选择的情况，不得用于表示参数不合法。
4. 预估和创建请求继续复用同一个服务端权威生成参数校验器。后端保留 `IMAGE_CAPABILITY_MISMATCH` 错误码，并在可以安全返回时补充字段和规则详情。
5. 模型支持 `auto` 时，新建或默认配置应选择 `auto`。
6. 已保存草稿、复用任务或用户手动选择的有效配置优先于默认值。模型不支持 `auto` 时，继续使用现有按比例或首个受支持选项的回退逻辑。
7. 保持现有规则：自动模式不传 `size`；透明背景只能输出 PNG 或 WEBP；暂不接入 stream 和 partial images；平台生成数量自动拆分逻辑不变。

### 5.4 创作页参数布局与接口契约

1. 将 `模型选择` 更名为 `模型分组`。
2. 模型分组使用支持键盘和无障碍操作的下拉框，并放在创作表单顶部。
3. 每个选项展示 `名称 · 最低 X 积分`。最低积分按当前用户实际倍率下，当前可见且启用的价格记录计算。
4. 资产引用区放在模型分组下方、提示词编辑器上方。
5. 移除 `限制词` 输入框，新任务不再发送或使用 `negative_prompt`。
6. 从当前公开 API、OpenAPI 和配置界面中移除 `negative_prompt`。兼容期内历史任务数据仍可读取。

### 5.5 提示词模板、资源与变量

#### 5.5.1 标准语法与解析规则

1. 资源占位符完整格式为 `{{@资源名称}}`，变量占位符完整格式为 `{{$变量名称}}`。
2. 只有完整闭合的占位符才会被解析。名称为空、占位符嵌套、未闭合、包含控制字符，或名称中含有 `{`、`}`、换行、制表符时，均视为非法模板语法。
3. 名称会去除首尾空白、执行 Unicode 标准化，区分大小写，长度为 1 至 64 个字符。持久化的标准占位符使用标准化后的名称。
4. `\{{@名称}}` 和 `\{{$名称}}` 表示普通文本，不产生绑定。转义反斜杠只在生成展开后提示词时移除，保存的原始模板保持不变。
5. 同一类型、同一名称的占位符可重复出现，所有出现位置共用一个绑定。
6. 资源和变量是两个独立命名空间，因此 `{{@主体}}` 与 `{{$主体}}` 可以同时存在。
7. 用户端与服务端的模板解析行为必须一致；创建任务时以服务端解析和校验结果为准。

#### 5.5.2 编辑器展示与校验

1. 创作页紧凑编辑器和展开弹窗编辑器都要把识别出的资源或变量占位符显示为蓝色行内 Tag，同时保持底层标准文本不变。
2. 鼠标悬停或键盘聚焦有效资源 Tag 时，展示图片预览、名称、尺寸和格式；有效变量 Tag 展示当前变量值。
3. 未匹配资源、未赋值变量、重复选择的同名资源或语法错误，使用红色 Tag 或错误标记，并展示明确原因。
4. 非法模板必须阻止创建任务，生成操作显示第一个可处理的模板错误，不能回退为 `等待参数`。客户端解析器负责即时提示，创建任务时由服务端再次执行权威校验。
5. 粘贴的富文本统一转换为纯模板文本，编辑器不得持久化 HTML 或编辑器库 JSON。
6. Tag 颜色、焦点样式、悬浮内容和错误状态不能只依赖颜色区分，必须同时提供图标、边框或文字等可识别信息。

#### 5.5.3 变量填写表单

1. 提示词编辑器正下方展示变量填写表单，并按变量在模板中首次出现的顺序列出所有去重后的变量。
2. 同名变量只展示一个填写控件；修改值后，所有同名占位符的预览同步更新。
3. 变量值仅属于当前草稿，初始为空，允许普通文本和换行，且不会被再次解析为嵌套模板语法。
4. 空值或只包含空白的值视为未赋值，并阻止生成。提交时只处理值边界的无意义空白，值内部有意保留的空格和换行不能丢失。
5. 单个变量值和最终展开后提示词都必须满足服务端提示词长度限制；用户端要指出具体超限字段和原因。

#### 5.5.4 引用资产命名与绑定

1. 每项上传或从图库导入的引用资产都必须有用户可见名称；迁移时为历史无名称资产分配确定性的默认名称。
2. 从图库导入的资产使用第一个可用友好名称，例如 `图片1`、`图片2`。上传资产优先使用合法的文件名主体，无法使用时再回退到上述序列。
3. 用户可以重命名自己拥有且有效的引用资产。名称标准化后，在该用户所有有效引用资产范围内必须唯一。
4. 在当前草稿内重命名资源时，同步更新草稿中匹配的资源 Tag；不得修改历史任务模板。
5. 只有当前已选引用资产中恰好存在一个标准名称匹配项时，资源占位符才有效。
6. 手动输入名称匹配的占位符不得静默复制或上传图片；从图库选择图片仍使用无复制引用别名流程。

#### 5.5.5 工具栏与自动补全

1. 两种提示词编辑器上方都展示紧凑图标工具栏，支持在当前光标位置插入资源和插入变量。
2. 插入资源菜单优先展示当前已选引用资产，并可以继续打开现有图库导入选择器。选择尚未加入草稿的图库图片时，先导入或挂载，再插入其占位符。
3. 插入变量菜单展示模板中已有变量，并支持创建一个名称合法的新变量。
4. 在光标位置输入未转义的 `@` 时打开同一资源菜单；输入未转义的 `$` 时打开同一变量菜单。
5. 选择菜单项后，用完整标准占位符替换触发字符和搜索文本；关闭菜单但不选择时，保留已输入字符作为普通文本。
6. 菜单必须支持键盘导航、Escape 关闭，并在关闭后把焦点恢复到原光标位置。

#### 5.5.6 任务创建与下游展开

1. 客户端只在创建任务时发送原始提示词模板、已选引用资产 ID 和名称绑定、变量名称和值绑定。价格预估不依赖提示词内容或绑定。
2. 创建任务前，服务端解析模板，校验资产归属和当前名称，要求每个变量恰好有一个值，拒绝未知的额外绑定，并生成一份展开后提示词。
3. 每个变量占位符替换为用户提交的变量值。已确认原报告中的“替换成真实的变量名称”实际表示“替换成用户在变量表单中填写的变量值”。
4. 每个资源占位符替换为该资产在最终下游引用列表中的位置：`图片1`、`图片2`、`图片3`，依此类推。同一资产被多次引用时复用相同下标。
5. 已选但未在模板中出现的引用资产仍保留在下游引用列表中，以兼容现有图片编辑行为。
6. Worker 只向图片供应商发送展开后提示词和有序图片列表，不发送原始占位符语法或变量绑定 JSON。
7. 客户端完成解析或绑定后，如果资产名称在点击创建前发生变化，服务端返回 HTTP 409 / `PROMPT_TEMPLATE_STALE`。客户端刷新名称并要求用户确认修复后的绑定。能力版本变化继续使用现有重新预估流程，服务端不得猜测资源绑定。

#### 5.5.7 历史记录、复用与提示词优化

1. 生成任务和图片展示并保留未展开的原始提示词模板，不展示展开后运行时提示词。
2. 复用历史提示词时，只复制原始模板和仍兼容的生成参数，不挂载原任务引用资产，也不复制变量值。
3. 复用后，资源占位符保持红色，直到用户重新挂载同名资源；变量字段重新创建且初始为空。
4. 提示词优化只接收受保护的占位符哨兵，不接收资源图片内容或变量值。
5. 优化器内置指令必须要求完整保留每个占位符。服务端在优化后校验完整占位符多重集合；发现新增、删除、改名或损坏时拒绝优化结果，原草稿保持不变。
6. 合法优化结果应用到当前草稿后，只在当前草稿内保留现有资源绑定和变量值。

### 5.6 资产页刷新与选择

1. 用户端私有资产页新增纯图标刷新按钮。项目页保留已有纯图标刷新按钮，两者使用相同加载和错误行为。
2. 刷新时保留当前项目和筛选条件，从第一页重新加载，并只保留刷新结果中仍存在的已选图片 ID。
3. 图片选中标识使用高对比度实色样式，在明暗缩略图上都必须清晰可见。
4. 未选中任何图片时，点击缩略图打开详情；进入选择模式后，点击缩略图只切换选中状态，不打开详情。
5. 桌面端鼠标或触控笔用户可以在已加载的可见卡片上拖出选择框批量选择。触屏操作继续用于滚动，不触发框选。
6. 普通拖拽用框内图片替换当前选择；按住 Ctrl/Cmd 拖拽时追加选择；Escape 清空选择。
7. 卡片操作按钮保持独立可点击，点击操作按钮不得切换选中状态。

### 5.7 后台订单与超时生命周期

1. 订单列表新增用户列，尽可能展示用户 ID、邮箱和昵称；用户已删除或缺失时回退展示不可变的 `user_id`。
2. 积分列分别展示基础积分、赠送积分和总积分。
3. 系统设置通过 `payments/order_timeout_seconds` 配置订单超时，默认 900 秒，并按文档定义的安全区间校验。
4. 固定套餐订单和自定义金额订单创建时，都按当时生效的动态超时计算并固化 `expires_at`。
5. 满足 `expires_at <= now` 的未支付订单，从 `pending` 幂等转换为内部状态 `expired`。
6. 用户端把 `expired` 展示为 `已取消（支付超时）`；内部仍将人工 `canceled` 与超时区分保存。
7. 后台扫描任务低频失败时，订单不能永久显示待支付；订单列表、详情和同步流程需执行受保护的惰性过期检查。
8. Worker 每 30 秒执行一次定时扫描，分批处理有限数量记录，并支持多个 Worker 并发运行而不重复流转。
9. 保持现有延迟支付对账能力：经过验证的支付回调或供应商查询结果，可以把已超时订单准确完成一次。

### 5.8 后台套餐管理

1. 套餐操作包括编辑、启用、禁用、软删除或归档、恢复。
2. 软删除后，默认后台列表和所有新购买入口不再展示该套餐，但不改变历史订单或当前有效积分和订阅。
3. 筛选条件包括套餐代码或名称模糊搜索、套餐类型精确筛选和状态精确筛选。
4. 服务端支持按价格、排序值和积分升序或降序排序；默认顺序为 `sort_order ASC, id ASC`。
5. 筛选条件不变时重复点击搜索，也必须发起新的请求。
6. 复用现有生命周期接口和审计行为，不另建一套并行变更接口。

### 5.9 管理后台列表统一刷新

1. 每个包含列表、表格、队列或配置集合的菜单页，都使用统一刷新图标提供手动刷新操作。
2. 至少覆盖运营总览、监控、集群、用户、用户组、审核队列、兑换码、订单、套餐、收银台配置、接入账号、路由、价格、调用记录、管理员、审计日志和系统设置。
3. 手动刷新时保留当前筛选、排序、分页、选择、活动页签，以及仍然有效的已打开弹窗。
4. 刷新过程中保留上次成功数据并展示非阻塞加载状态；失败时继续保留原数据并提示错误。
5. 较早发起的请求不得覆盖较新的刷新结果。
6. 即使字段值未变化，点击搜索或筛选也必须发起请求。

### 5.10 支付方式展示与隐私

1. 支付方式使用本地打包的官方品牌图标，例如支付宝、微信支付和 Stripe；未知方式使用中性默认图标。
2. 支付选项使用紧凑响应式网格，不再让一个选项占据整行宽度。
3. 用户端只展示公开支付方式，不得暴露 JeePay、EasyPay、direct/manual 适配器、供应商实例 ID、调度策略或其他渠道实现细节。
4. 用户端收银台选项和订单 DTO 与后台 DTO 分离。用户 DTO 可返回界面行为所需的公开展示或流程提示，但不能返回选中的内部供应商。
5. 缺少 `visible_method` 的历史订单，由服务端映射为公开支付方式名称后再返回。
6. 模拟支付标识只允许在非生产环境展示。

## 9. 已确认业务决策

### 9.1 订单超时状态展示

- 确认结论：内部使用独立状态 `expired`，用户端展示为 `已取消（支付超时）`；人工取消继续保存为 `canceled`。
- 实现影响：后台筛选、统计、监控和延迟支付对账均需区分系统超时与人工取消；用户端只展示清晰的支付超时结果。

### 9.2 变量占位符的实际替换内容

- 确认结论：原描述中的“变量名称”实际指用户在变量表单中填写的“变量值”。
- 展开示例：模板为 `穿着 {{$服装}}`，变量表单填写“蓝色风衣”后，下游收到 `穿着 蓝色风衣`。
- 实现影响：变量表单中的值参与最终生成；Tag 悬浮预览展示同一值；历史记录和复用仍不得保存或恢复旧变量值。
