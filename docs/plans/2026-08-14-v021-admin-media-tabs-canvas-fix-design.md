# v0.0.21 管理后台媒体模型配置与画布兼容修复设计

## 1. 背景与目标

`v0.0.20` 已具备视频账号、真实模型、路由候选、能力、成本和销售价格的后端数据结构，但管理端仍将视频配置集中在需要手填数据库 ID 和 JSON 的工作台中，没有完成需求文档约定的图片、视频、音频、文本四类 Tab，也没有形成与图片模型一致的层级化管理体验。

空白画布创建时，Go 的 `nil` slice 被序列化为 `null`。前端编辑器和列表分别直接调用 `map`、`slice`，因此新画布无法打开，返回列表后继续白屏；通用 HTTP 客户端又将本地 `TypeError` 误判为网络异常，掩盖了真实原因。

本次目标：

- 三个管理页面统一按媒体类型拆分 Tab，并把选中状态保存在 `media` 查询参数中；
- 视频配置形成“账号 -> 真实模型 -> 路由模型及候选 -> 参数价格策略”的可视化层级，不要求管理员手填内部 ID；
- 音频明确为预留空状态，文本迁移既有入口，不虚构尚未实现的路由能力；
- 新旧画布文档中的 `nodes`、`edges` 对外始终为数组，并对历史 `null` 数据读时兼容；
- 保持现有视频运行时候选、回退、计费快照和历史数据兼容。

## 2. 管理后台信息架构

三个页面共享媒体类型：

```text
image | video | audio | text
```

URL 约定：

```text
#/access-accounts?media=image
#/routing?media=video
#/pricing?media=text
```

未知或缺失值回退 `image`。使用平台现有 `AdminTabs` 和表格、抽屉、弹窗、图标按钮，不引入浏览器原生突兀控件。

### 2.1 接入账号

- 图片：保留现有账号和真实模型主从管理，仅显示图片适配器。
- 视频：复用 `model_accounts -> model_account_models`，账号支持 `seedance`、`minimax`，一个账号可管理多个真实模型；选中模型后用结构化表单维护能力和成本规则。
- 音频：展示预留状态，无新增按钮。
- 文本：嵌入现有文本模型管理，保留原权限和密钥处理。

视频能力和成本仍写入已有 `video_model_capabilities`、`video_provider_cost_rules`，不创建重复账号或模型表。厂商扩展项只放入扩展 JSON，通用字段必须结构化编辑。

### 2.2 路由模型

- 图片、视频分别按 `route_models.media_type` 过滤。
- 视频路由支持多个候选；候选选择器只提供启用账号下、已配置有效视频能力的真实模型。
- 选中视频路由后自动读取 `video_route_configs`，不再手填路由 ID。
- 候选权重、优先级、启停、默认参数、用户可见组合均结构化编辑。
- 文本只展示当前默认文本模型状态和入口，不伪装成通用多候选路由。

### 2.3 价格策略

- 图片价格只关联图片路由，避免与视频路由混合。
- 视频展示策略列表、参数规则、启停、删除和试算；选中策略与路由时自动传递内部 ID。
- 文本复用输入/输出百万 Token 成本配置，并明确其为成本而非完整销售策略。

现有运行时是“路由配置绑定一个默认策略，策略内按参数匹配价格规则”。为满足“基于参数关联不同价格策略”且保持历史兼容，本期在 `VideoRouteConfig.visible_options` 中保存可选 `pricing_bindings`：

```json
[
  {
    "task_type": "text_to_video",
    "resolution": "720p",
    "audio_mode": "silent",
    "duration_seconds": 5,
    "pricing_strategy_id": 12
  }
]
```

报价时先按完整参数匹配绑定策略，未命中则回退既有 `pricing_strategy_id`。历史配置无需迁移，计费快照仍保存最终命中的策略和规则。

## 3. 画布数据兼容

### 3.1 后端不变量

新增统一文档归一化函数：

- `schema_version`、viewport 保持既有默认逻辑；
- `nodes == nil` 转为空切片；
- `edges == nil` 转为空切片；
- 模板创建、保存前归一化、数据库读取投影、API 返回均经过该函数。

这样新画布写入 `[]`，数据库中既有 `null` 画布无需迁移，也会在读取时返回 `[]`。

### 3.2 前端防御

在画布 API 边界提供 `normalizeCanvasDocument`：

- 非数组 `nodes/edges` 归一化为空数组；
- 编辑器、列表、保存状态统一消费归一化结果；
- 列表预览额外保留 `Array.isArray` 防御，单条坏数据不得拖垮页面。

本地文档结构错误不再由页面包装成“网络异常”；显示可理解的数据加载错误，并保留返回列表能力。

## 4. 兼容性与安全边界

- 不改变图片模型运行时和视频候选选择算法。
- 不删除已有视频工作台 API；新页面复用并逐步替代手填入口。
- 不修改历史任务、账单和价格快照。
- 文本模型迁移不扩大 `manage:models`、`manage:dangerous_config` 权限。
- 旧 `#/system-settings?tab=text-models` 定向到新文本接入账号页。
- 音频只展示真实能力边界，不允许创建无运行时支持的配置。

## 5. 验收标准

1. 三个页面均有四类 Tab，刷新和复制 URL 后仍保持所选媒体类型。
2. 可创建多个视频账号，每个账号可创建多个真实模型并配置能力和成本。
3. 可创建多个视频路由，每个路由可绑定多个有效视频真实模型。
4. 视频价格规则和参数策略绑定可结构化维护并通过试算验证。
5. 管理员不需要手填账号、模型、路由、策略的数据库 ID 或通用 JSON。
6. 新建空白画布能进入编辑器；返回列表不白屏。
7. 历史 `nodes:null/edges:null` 画布也能打开和预览。
8. Go、前后端构建、contract、API smoke、浏览器桌面与平板横屏验收通过。
