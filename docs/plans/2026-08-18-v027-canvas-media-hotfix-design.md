# v0.0.27 画布与媒体上传兼容修复设计

## 背景

本次修复覆盖无限画布图片生成、提示词模板、资产选择与媒体兼容上传四条链路。目标是在不新增用户配置项、不改变创作页既有语义的前提下，让画布按真实输入自动选择生成能力，并恢复 Cloudflare R2 下的服务端代理上传。

## 设计决策

### 1. 图片生成任务类型由实际输入推导

- 图片生成节点没有参考图片时使用 `text_to_image`。
- 连接至少一张参考图片时使用 `image_edit`。
- 前端以推导出的任务类型选择模型能力、参数校验和费用预估，不再依赖草稿中可能过时的 `task_type`。
- 任务类型变化时优先保留当前模型；当前模型不支持时自动选择首个支持该任务类型的模型，并将尺寸、质量和输出格式归一到对应任务能力。平台多图拆分数量不按真实模型单次输出上限截断。
- 若当前没有支持推导任务类型的模型，节点必须展示明确的模型能力错误，不得只显示没有原因的“等待参数”。
- 后端在提交前根据 `ReferenceAssetIDs` 再次推导任务类型，保证历史画布和被篡改请求也遵循相同规则。
- 新建图片生成节点优先选择支持 `text_to_image` 的模型分组；不增加手动“生成方式”字段。

### 2. 画布提示词复用创作页组件

- 画布提示词节点直接复用 `PromptTemplateEditor` 与 `PromptVariableForm`。
- 变量和资产 Tag 的渲染、有效/无效状态、删除、悬浮预览、`@`/`$` 唤起与取消行为均由共享组件提供。
- 画布连线得到的图片资产转换为共享编辑器需要的 `ReferenceAsset` 视图模型，并提供授权预览地址。
- 画布保留节点标题和提示词优化动作；提示词文本与变量值仍保存在节点 payload 中。

### 3. 资产选择使用“原图可引用”语义

- 画布资产抽屉不再固定传 `status=ready`。
- 查询当前项目的图片资产后，仅排除明确不可用的上传中或已删除记录；`processing`、`processing_failed` 等派生处理状态不阻止引用原图。
- 资产归属与访问权限仍由服务端按用户和项目校验。

### 4. R2 兼容上传不发送可选校验头

- 浏览器直传的预签名 URL 只签名 `host`，不再要求浏览器发送 `X-Amz-Checksum-Sha256`，避免该请求头触发 R2 CORS 预检拒绝。
- 服务端代理 `UploadPart` 保留 SigV4 必需的 `X-Amz-Content-Sha256`。
- 不发送 `X-Amz-Checksum-Sha256`，避免 Cloudflare R2 对未支持的 UploadPart 校验扩展返回错误。
- 服务端继续用 `io.TeeReader` 计算实际 SHA-256，并与客户端声明值比对，内容完整性校验不降低。
- AWS S3、MinIO 与 R2 共用同一条兼容路径，不引入厂商分支。

## 兼容性与风险

- 历史画布中保存的 `task_type` 继续保留，但执行时以真实参考图输入为准。
- `processing_failed` 资产可能缺少缩略图，选择器应使用现有原图降级预览逻辑。
- 直传是否成功仍取决于对象存储 CORS；直传失败后的服务端兼容模式必须独立可用。
- 上传失败日志保留对象存储状态码和有限响应摘要，但不得记录密钥、授权头或完整签名 URL。

## 验收标准

1. 无参考图的画布图片节点可估价并创建文生图任务。
2. 连接参考图后，同一节点自动按图片编辑能力估价并创建编辑任务。
3. 当前模型不支持图片编辑但存在其他可用模型时自动切换；完全没有可用模型时显示明确原因。
4. 提示词节点的资源和变量 Tag 行为与创作页一致。
5. 当前项目存在派生处理失败的图片时，画布资产选择器仍能列出并选择。
6. 模拟 R2 拒绝 `x-amz-checksum-sha256` 的测试中，兼容分片上传成功，且错误 checksum 仍被服务端拒绝。
