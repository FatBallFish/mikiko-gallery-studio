# 统一媒体资产实施设计

日期：2026-11-01
需求：`docs/prd/2026-11-01-unified-media-references-requirements.md`

## 数据与兼容

- `media_assets` 是权威实体。图片参考 DTO 可以保留兼容接口形状，但从统一媒体记录投影，不再要求调用方创建 reference alias。
- 历史独立参考图使用原 UUID 回填统一媒体，归入用户默认项目；已有关联媒体/生成结果的 alias 指向现有媒体，避免相同对象重复建档。
- 保留历史 reference 行作为旧 ID 兼容映射，不删除历史数据或物理对象。移除旧的 active-media alias 唯一索引，允许多个历史 ID 永久指向同一媒体；保留普通查询索引。读取旧 ID 时映射到统一媒体并实施 owner、type、status、deleted 校验，不能因旧 alias ready 绕过当前状态。
- 自动迁移复用启动数据库初始化及现有回填基础设施，事务保护资产创建、映射及对象所有权；幂等运行不覆盖用户后续重命名、移动、删除，不复活已删除数据。多实例启动必须保持唯一性。
- 旧上传接口若继续兼容，也必须立即写入统一媒体，不能依赖下次启动才可见。统一媒体拥有文件生命周期，旧 alias 不能误删共享文件。

## 上传与任务

- 新客户端使用统一上传会话：初始化、分片上传（直传/代理）、完成、查询处理状态。
- 图片任务参考 IDs/命名绑定直接接受统一媒体 ID；历史引用 ID 由服务端兼容解析。提交前及执行加载均验证图片类型和 ready/ready_original 状态，返回可辨别的处理中/处理失败错误。
- 视频保持 unified media 输入契约，并对齐状态错误提示。
- MCP 源码位置先通过仓库及明确关联路径查证；若工具实现独立于本仓库，修复本仓库对外协议、兼容接口和文档，并明确外部部署边界。

## 前端

- 进入画布同步其所属项目；画布上传、抽屉列表和返回资产页保持一致。
- 抽屉在服务端传媒体类型，使用 next_cursor 加载更多、去重并防止旧请求覆盖新项目结果。上传事件刷新，处理中资产轮询；不可引用项显示准确原因并禁止选择/拖入。
- 普通工作台改用统一上传，引用 DTO 从媒体投影，移除显式 alias 转换调用。异步处理完成前不提示可编辑。
