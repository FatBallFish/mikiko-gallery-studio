# v0.0.26 视频、画布与上传修复设计

## 1. 设计摘要

本次修复采用三条共享原则：能力只维护一个事实源、运行时校验与展示使用同一语义、画布异步结果由服务端幂等归位。

- 视频可选参数由真实模型能力计算，不再由路由模型重复配置。
- 所有路由可见性关联统一读取，视频运行时补齐用户组上下文。
- 上传保留浏览器直传的成本优势，并以同源 API 流式分片作为可靠性兜底。
- 画布复用现有节点 Schema，增加尺寸命令、空图片框状态和服务端结果槽位归位。

## 2. 视频能力单一事实源

### 2.1 删除路由可见组合

删除管理端表单、共享类型、管理请求及 `visible_options.combinations` 的保存和启用校验。数据库历史 JSON 不要求迁移，读取路径忽略该字段。

`videorouting.Service.Capabilities` 继续遍历路由候选，但只接受启用账号、启用账号模型和 `verified` 能力。对每个任务类型调用能力展开函数，形成候选支持组合的并集，以任务类型、时长、分辨率、比例和音频模式去重。

能力并集只负责告诉用户“至少有一个候选可以执行”。`Resolve` 在报价和创建时对完整请求逐候选执行 `Capability.Match`，没有候选匹配时返回 `VIDEO_CAPABILITY_MISMATCH` 和 `field_errors`。

### 2.2 可见性上下文

视频路由存储接口增加用户组代码参数：

```go
GetVideoGroup(ctx context.Context, code string, userGroupCodes []string) (Group, error)
ListVideoGroups(ctx context.Context, userGroupCodes []string) ([]Group, error)
```

存储层加载路由后按以下规则判定：

```text
hidden -> 拒绝
public -> 允许
groups -> 路由关联组 ID 与当前用户启用组 ID 有交集时允许
```

能力 handler 从已认证用户取得 `userGroupCodes(user)`。视频报价和创建请求已经包含用户身份，服务层在路由解析时传入相同代码。画布生成沿用 `GenerateRequest.UserGroupCodes`。

### 2.3 管理端回显

`ModelAdminStore.ListRouteModels` 批量查询当前页路由 ID 对应的 `RouteModelVisibilityGroup`，构建 `map[routeModelID][]groupID` 后映射，避免逐行查询。详情接口查询单个路由关联。创建和更新返回保存后的关联集合。

这套映射不区分媒体类型，因此同时修复图片、视频、音频和文本路由。

## 3. 上传直传与流式兜底

### 3.1 客户端状态

上传快照增加 `transport: direct | proxy`，新会话默认 `direct`。S3/R2 分片流程：

1. 请求签名目标；
2. 浏览器 `PUT`；
3. 若响应成功，读取 `ETag`；
4. 若 `fetch` 抛出网络错误，或预签名目标无法形成可读响应，则将会话切换为 `proxy`；
5. 当前分片和后续分片调用同源上传 API。

对象存储返回明确 HTTP 4xx/5xx 时保留原错误，不把权限或签名错误一律伪装成 CORS。只有浏览器不可达类错误触发自动降级。

### 3.2 服务端分片转发

现有媒体分片 API 从仅本地存储扩展为所有实现 `MultipartBackend` 的后端。`S3Backend.PutMultipartPart` 使用声明的 SHA-256 作为 SigV4 payload hash，直接以请求流作为上游 body，并设置准确 `Content-Length`，不缓冲整个分片。

转发前校验：会话归属、状态、分片序号、预期分片大小、内容长度和 SHA-256 格式。R2 返回成功后解析 `ETag` 并记录已完成分片。

客户端仍以 16 MiB 默认分片和有限并发上传，因此 1 GiB 文件不会作为单个请求进入 API。代理路径增加请求超时和取消传播。

### 3.3 CORS 诊断

存储配置页基于 provider 展示 R2/S3 浏览器直传要求。探测结果增加非阻断提醒，列出当前前端 Origin、允许方法、允许请求头和暴露响应头。平台不自动调用 `PutBucketCors`，避免要求高权限凭据或覆盖用户已有规则。

## 4. 画布交互基础

### 4.1 事件边界

节点拖动从整张 `article` 收缩到标题栏和显式拖动区域。以下元素统一标记 `data-canvas-interactive` 并停止启动拖动：按钮、输入框、textarea、select、媒体控件、滚动容器、端口和缩放手柄。

节点选择仍可在交互控件点击前完成，但不设置 pointer capture。连接端口继续独立捕获指针。

### 4.2 尺寸命令

状态层增加纯函数 `resizeCanvasNode` 和 store action `resizeNode`。缩放会形成一条可撤销命令，最小尺寸按节点类型计算：

| 节点 | 最小宽高 |
| --- | --- |
| 提示词、便签 | 220 x 140 |
| 图片、视频 | 220 x 160 |
| 音频 | 240 x 120 |
| 图片/视频生成 | 280 x 200 |

视图在选中节点右下角展示缩放手柄。移动过程使用临时尺寸，pointer up 时除以当前 zoom 后提交一次命令，避免每帧污染撤销历史。后端补充有限数值、坐标范围和最小尺寸安全校验。

## 5. 图片框

### 5.1 Schema 兼容

保持 `CanvasNodeType=image` 和 `schema_version=1`。图片节点分为：已绑定图片（`asset_id` 非空）和空输出框（`asset_id` 为空，且存在一条 `image_generation -> image`、角色为 `result` 的入边）。

文档校验分两阶段完成节点和边索引后再检查空图片节点。没有合法结果入边的空图片节点拒绝保存。资产引用提取忽略空框。

### 5.2 创建和填充

工具栏和空白节点菜单增加图片框入口。新建空框先存在本地草稿中；只有连接为输出位后才可成功保存。若用户直接选择资产或上传，节点获得 `asset_id` 后可独立保存。

图片框内部提供从资产库选择、本地上传单张支持格式图片，以及已加载图片的预览、详情、下载和继续创作操作。

上传队列事件携带可选 `canvas_id/node_id` 目标。完成事件回传目标和资产 ID；仍打开同一画布且节点存在时填充节点。页面关闭不影响资产上传完成，用户可稍后从资产库选择。

## 6. 提示词资源候选

对提示词节点计算相关生成节点：提示词通过 `prompt` 边连接到生成节点，再收集这些生成节点的 `reference` 图片输入。去重后形成候选资源列表。

“资源”按钮打开与创作页一致的轻量选择弹层，展示缩略图和名称。选择后用 textarea selection range 在光标处插入 `{{@名称}}`，并保持焦点。连接动作本身不修改提示词。

生成时仍由 `buildCanvasPromptBindings` 和后端 `promptReferenceBindings` 按名称绑定资产 ID。重名时使用稳定连线顺序并提示名称冲突，要求用户重命名后再生成。

## 7. 图片生成自动估价与数量

图片生成节点根据文档签名维护估价状态：`idle | waiting | loading | ready | error`。输入完整且没有字段错误时，文档变化 300ms 后自动保存并调用估价接口。请求使用 AbortController 或请求序号忽略过期响应。

`ready` 时直接展示预计积分和“确认生成”。点击时要求当前文档签名与估价签名一致；否则清除旧估价并触发新估价。视频节点不改变现有显式报价交互。

图片数量控件复用创作页的 `normalizeWorkspaceImageCount` 和平台任务安全上限，改为数字步进器，不使用由真实模型原生 `n` 推导的下拉选项。后端继续由图片任务服务按候选 `MaxImageCount` 拆分调用。

## 8. 结果槽位和始终追加

运行记录的第一次归位按以下顺序执行：

1. 读取该生成节点现有 `result` 出边；
2. 选择尚无 `asset_id` 的图片节点作为空槽，按边 ordinal 和文档顺序排序；
3. 用本次结果依次填充空槽；
4. 为剩余结果创建稳定 ID 图片节点和结果边。

生成节点只在从未成功归位过结果时消费预连空槽。是否首次以该节点已有已附加运行记录为准，而不是以当前是否仍有空框猜测。

第二次及以后每次运行都为全部结果创建新节点。布局以运行批次为列、结果序号为行，避免覆盖历史节点。节点 ID 继续由运行 ID 与资产 ID 稳定生成，重复刷新保持幂等。

存储 Attach 接口扩展为同时支持更新已有节点的 `asset_id/payload` 和新增节点/边，并在一个 CAS 修订事务内完成。修订冲突时保持 `unplaced`，允许用户恢复到当前视图。

## 9. 错误处理

- 能力不匹配：返回字段错误，用户端定位具体参数。
- 路由不可见：统一 403，不泄露隐藏路由候选。
- 自动估价输入不完整：本地显示缺失项，不发请求。
- 自动估价网络错误：保留参数，显示重试状态，不允许使用旧估价。
- 上传直传失败：标记“已切换兼容上传”；代理失败显示分片和服务端错误。
- 空图片框未连接：保存状态明确提示“请选择图片或连接生成输出”。
- 结果归位冲突：任务和资产保持成功，仅画布进入可恢复状态。

## 10. 测试设计

1. Go 单元测试覆盖视频能力聚合、可见性、管理回显、S3 流式分片、画布校验和结果归位。
2. HTTP 合约测试覆盖用户组视频能力/报价/创建、管理路由详情、媒体代理分片和画布保存。
3. 前端纯函数与 contract 测试覆盖尺寸命令、事件命中、自动估价状态、上传降级、资源候选和数量上限。
4. 浏览器验收覆盖桌面端与平板横屏：调整尺寸、提示词按钮、自动费用、单图/多图/再次生成、图片框资产选择和上传。
5. 完成后运行 `verify.sh`、提交范围 review gate、API smoke 和必要的浏览器截图验收。
