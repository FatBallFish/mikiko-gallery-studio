# Admin Runtime Monitoring Acceptance

Date: 2026-07-12

Environment: Docker development stack at `http://127.0.0.1:8088/admin/`

## API and runtime telemetry

- Rebuilt `api`, `admin-web`, and `nginx`; all Compose services reported healthy.
- Authenticated as the development administrator and generated 12 requests to `GET /api/ops/admin/v1/metrics/dashboard`.
- After one complete five-second sample, `GET /api/ops/admin/v1/monitoring/snapshot?window=5m` returned `collecting: false` and a hot route named `GET /api/ops/admin/v1/metrics/dashboard` with 12 requests. No `GET unknown` fallback was present for those routed requests.
- The `5m`, `15m`, `30m`, and `60m` controls each selected and loaded successfully. The page returned to the default `15m` window.

## Interaction and accessibility

- The automatic-refresh control exposes `role="switch"` and `aria-checked`; the previous hidden-checkbox page overflow is absent.
- With automatic refresh disabled, no monitoring snapshot request occurred during a 6.2-second interval. Re-enabling it restored successful snapshot polling.
- While the monitoring tab was hidden for 6.2 seconds, no snapshot request occurred. Returning to the tab triggered an immediate refresh.
- The request-load chart accepted `Home`, `End`, `ArrowLeft`, and `ArrowRight`; keyboard focus showed a 2px solid outline.
- `prefers-reduced-motion: reduce` was detected by the page during acceptance.
- Browser console and page-error collections were empty after the monitoring and Dashboard checks.
