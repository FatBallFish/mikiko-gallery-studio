# Mikiko Gallery Studio 前端重构 Prompt

> 将本文件完整交给执行重构的 AI。原型目录：`prototypes/redesign/`。本文件是设计验收后的最终重构指令，优先级高于执行者的个人偏好。

## 0. 角色与目标

你是一名资深前端架构师与 UI 重构工程师。请基于已经验收通过的静态原型 `prototypes/redesign/`，对现有项目的用户端（`web/user`）和管理端（`web/admin`）做一次**彻底的前端重构**，使生产页面在视觉、布局、组件、交互和响应式行为上与原型一致，同时保留并补齐真实业务功能。

这不是“换一套颜色”或“局部美化”。你需要：

1. 严格按照原型的样式、布局、组件规范和交互方式实现。
2. 不允许遗漏原型中的页面、组件、状态、交互和响应式规则。
3. 原型是静态演示，数据是虚构的；生产实现必须接入项目真实 API、权限、路由和业务状态，不能把 mock 数据、picsum 图片、纯 toast 演示当成成品。
4. 原型没有完全覆盖的生产功能，按照原型已有的设计系统、组件模式和交互范式补全，不允许另造一套视觉语言。

## 1. 权威来源与优先级

按以下顺序判定冲突：

1. **业务规则、接口契约、权限、安全、计费、审核**：以现有生产代码、后端类型和文档为准。
2. **视觉、布局、组件、交互、响应式**：以 `prototypes/redesign/` 为准。
3. **原型未覆盖的生产功能**：按原型设计系统补全，并在实现说明中记录补全依据。
4. **原型与生产功能冲突**：不得静默删除生产功能；保留功能，用原型的组件和布局重新表达。

## 2. 硬性约束

### 2.1 必须遵守

- 先审计、再计划、再实现。不要直接开始改页面。
- 严格复用原型的设计 token、间距、字号、圆角、动效曲线、断点和组件结构。
- 用户端必须保留原型的两套主题能力：深色 `Luminous Vault` 为默认，浅色 `Paper` 可切换。
- 管理端必须使用原型的 `Command Deck` 体系：暖灰纸面、白色面板、墨色文字、单一墨蓝强调。
- 所有列表统一为：筛选带 + 数据表格 + 分页器。
- 所有多级详情、编辑、配置统一进右侧抽屉；复杂配置使用二级抽屉叠加，上级不关闭。
- 所有表单使用单列字段账本；只有同高短字段允许成对。
- 所有媒体详情使用一套统一组件，不允许图片、视频各维护多套详情。
- 所有响应式断点、移动端降级、横向滚动容器必须实现。
- 所有交互必须有 loading、empty、error、disabled、hover、active、focus、selected 状态。
- 所有颜色、字号、间距、圆角、阴影必须来自 token 或原型中明确的值。
- 所有真实数据必须来自现有 API；原型中的假数据、picsum、纯 toast 只能作为交互占位，不能进入生产逻辑。
- 保留现有权限、计费、审核、任务状态、错误码和 API 契约。
- 修改后必须通过仓库验证流程。

### 2.2 禁止

- 禁止把静态 HTML 直接粘贴进 React 页面。
- 禁止在旧组件上叠加新样式来“凑视觉”。
- 禁止保留旧版媒体详情、旧版表单、旧版列表样式与新体系并存。
- 禁止只做桌面端。
- 禁止遗漏原型中的页面、抽屉、页签、枚举映射、空状态和错误状态。
- 禁止引入新的 UI 组件库、图标库或 CSS 框架，除非项目已经使用。
- 禁止使用未定义的颜色、字号、圆角、间距“临时值”。
- 禁止用 mock 数据替代真实接口，禁止把原型里的 `data-toast` 演示当成业务反馈。
- 禁止破坏现有路由、权限、API 请求和返回结构。
- 禁止把原型中不存在的页面/功能静默删除。

## 4. 用户端必须落地的规范与行为

### 4.1 视觉与外壳

- 默认深色：`#08090d` 背景、暖象牙文字、琥珀强调、mono 元信息、胶片颗粒与光晕。
- 圆角收敛为 6 / 10 / 14 / 20 / 28 五档；间距按 8pt 节奏。
- 92px 图标 rail + 72px 顶栏；rail 有滑动指示器、按压反馈。
- 移动端 rail 降级为底部五项导航。
- 顶栏包含项目切换、通知、分级积分余额、头像。
- 头像点击弹出菜单：个人中心、积分充值、API 密钥、开发文档、退出登录。
- 账户页（个人资料/API 密钥/外观偏好）不再使用二级账户菜单。

### 4.2 统一媒体详情

- 图片与视频共用一套详情 Drawer。
- 桌面两列：`minmax(0,1fr) / 392px`；舞台固定高度 `clamp(320px, 58vh, 660px)`。
- 媒体始终 `object-fit: contain`，任意原始比例不改变舞台和信息列布局。
- 信息列独立滚动；标题、Prompt、参数、来源、操作位置固定。
- 移动端单列：舞台在上，信息在下。
- 卡片点击媒体只打开抽屉，不跳转详情页。
- 抽屉右上角「分享」左侧有「详情」按钮；进入详情页后，返回按钮按来源原路返回，默认才回资产库。
- 详情页支持 1:1 / 4:5 / 16:9 / 9:16 切换且舞台高度稳定。

### 4.3 积分展示

- 余额与消耗按四级换算展示：钻石积分、金币积分、银币积分、积分。
- 汇率文案：
  - 1 钻石积分 = 100 金币积分
  - 1 金币积分 = 100 银币积分
  - 1 银币积分 = 100 积分
  - 100 积分 = 1 元（1 积分 = 0.01 元）
- 余额与流水按等级自动换算；积分包和订单记录保留原始积分值。
- 参考生产实现 `web/shared/pointsDisplay.ts`，不要另写一套换算规则。

### 4.4 创作台

- 图片创作参数顺序固定：模型 → 提示词 → 参考图 → 尺寸 → 质量 → 数量。
- 图片/视频生成切换使用分段控件，样式必须与原型一致。
- 估价与提交固定在参数列底部。
- 视频结果组件必须与图片结果同构：
  - 媒体居中舞台。
  - 中间播放按钮。
  - hover 时右上角出现快捷菜单。
  - hover 时左下角出现参数说明。
  - 不再使用“视频左、参数右”的双列结果布局。

### 4.5 其他用户端细节

- 资产统计卡第一项保留左侧内边距。
- 公开广场的模型筛选下拉必须使用统一 `.u-filter` 样式。
- 亮色主题下主色按钮顶部不得出现 1px 深色描边。
- 设置页强调色与样式示例之间保留间距。
- 设置页不展示 reduced-motion 说明文案。
- 所有主色按钮、次操作、轻量、危险按钮状态完整。

## 5. 管理端必须落地的规范与行为

### 5.1 视觉体系

- 暖灰纸面 `#f2f1ec`、白色面板、墨色文字、单一墨蓝强调 `#2e4a7d`。
- 248px 浅色侧栏；不再使用旧版暖灰纸面之外的旧视觉。
- 字号：页面标题 30px、区块 15px、正文 15px、表格 14px、标签 13px、辅助 12.5px、机器字段 11px mono。
- 行高 1.55；数字 `tabular-nums`。
- 侧栏用户组件：头像字符垂直水平居中；名称、邮箱、角色与退出按钮使用同一垂直中线；退出按钮占满整行并居中。

### 5.2 表单

- 单列字段账本：标签在上、控件全宽、帮助文本在下。
- 仅允许同高短字段成对，且同一 grid 行。
- 长表单拆 section，使用编号 + 标题 + 一句说明。
- 保存栏 sticky；显示未保存数量与校验结果。
- 多值枚举使用下拉多选 + 自定义值输入组件；不得用逗号分隔文本框代替。

### 5.3 列表

- 统一 `filter band + data table + pager`。
- 行高 56px；表头 sticky；数字右对齐 mono；状态使用语义 badge。
- 操作列使用 32px 按钮与 36px 图标按钮。
- 分页器统一页码、总数、每页条数与跳页。
- 表格必须放在横向滚动容器内，页面本身不得横向溢出。

### 5.4 抽屉与嵌套

- 常规 720px，复杂 1020px。
- 头部固定身份与状态；body 可分页签；底部固定操作。
- 二级抽屉打开时上级抽屉保持打开；关闭二级后回到上级。
- 关闭顶层时清理所有二级抽屉、scrim 与滚动锁。
- 支持 Esc、关闭按钮、点击遮罩关闭。
- 生产实现必须补齐焦点陷阱、初始焦点、关闭后焦点归还。

### 5.5 实体映射与枚举

- 用户：头像 + 名称 + 邮箱；点击打开摘要，可进入完整用户抽屉。
- 路由/模型：名称 + code + 账号；缺失映射回退原始 ID 并标灰。
- 任务状态、结算状态、支付状态、审核状态全部中文标签 + 语义色。
- ID 仅以 mono 小字用于复制/排障，不作为主信息。

### 5.6 接入账号（图片/视频差异化）

- 图片/视频页签必须真正切换内容，新增账号按钮随页签切换目标。
- 图片账号：OpenAI 兼容 / OpenRouter、Base URL、API Key、gpt-image-2 来源模式、账号状态、优先级、权重、并发、超时。
- 视频账号：Seedance / MiniMax / Gasic / 阿里百炼适配器、Base URL、API Key、账号状态、优先级、权重、并发、超时。
- 图片真实模型的能力字段：
  - 任务类型：文生图、图片编辑。
  - 基础分辨率、质量参数、尺寸模式、支持比例、支持像素尺寸。
  - 自定义比例、自定义尺寸及最小/最大宽高。
  - 支持背景、输出格式、支持输出压缩质量。
  - 审核等级、最大出图数、最大参考图、单图成本、币种、启用状态。
- 视频真实模型的能力字段：
  - 任务类型：文生视频、图生视频、首尾帧生视频、参考生视频、视频编辑、视频延长。
  - Provider 原生最大 n、提示词最大字符数。
  - 支持时长、支持分辨率、支持比例、音频模式。
  - 输入图片格式、单张输入上限。
  - 厂商原生费率（Seedance Token / MiniMax 按秒 / 百炼按秒 / Gasic 按次）。
  - 能力验证状态、启用状态。
- 视频模型不得出现质量、尺寸模式、支持背景、输出压缩、输出格式、审核等级等图片侧字段。
- 图片模型不得出现视频任务类型或视频参数。
- 真实模型列表从操作列「模型配置」进入；模型编辑使用二级抽屉，上级不关闭。
- 按账号切换模型配置抽屉时，标题、统计和模型列表必须随之更新。

### 5.7 路由模型（图片/视频差异化）

- 图片/视频页签必须真正切换内容，新增路由按钮随页签切换目标。
- 模型分组：图标展示、新建、编辑、删除；分组代码创建后不可修改。
- 图片路由编辑：
  - 基础信息、可见性、分组、排序、启用状态、路由图标。
  - 图片价格按「任务类型 × 基础分辨率 × 参考图倍率」维护。
  - 缺价组合必须在提交前阻断。
- 视频路由编辑：
  - 基础信息、可见性、分组、排序、启用状态、路由图标。
  - 视频参数：平台最大输出数、状态、最低任务积分、积分取整步长、默认任务/时长/分辨率/比例/音频、候选分辨率映射。
  - 视频报价：候选厂商原生费率、费率版本、最高销售价、全局汇率、单结果积分、总积分。
  - 不允许手工填写视频每秒售价；售价由候选原生费率 + 最高成本 + 汇率 + 最低积分/取整推导。
  - 未映射的分辨率不参与报价，必须在提交前阻断。
- 价格策略不再作为独立菜单；生产系统将入口统一到路由编辑抽屉，原路由可保留兼容跳转。
- 不得把模型能力字段（帧率、镜头运动、支持生成方式、参数映射 JSON）错误地放在路由层。

### 5.8 系统设置-存储配置

- 存储编辑改为抽屉。
- 存储列表操作列包含「探测连接」「设置默认」「编辑」。
- 编辑抽屉内保留「探测连接」。
- 「设置默认」不再放在编辑表单底部。
- 切换默认实例不迁移历史对象，界面必须提示。

## 6. 原型未覆盖功能的补全规则

生产功能可能多于原型。遇到原型没有对应页面的情况，按以下规则处理：

1. 先在生产代码中确认该功能的真实路由、API、权限和数据字段。
2. 从原型中复用最接近的页面骨架：
   - 列表页：筛选带 + 表格 + 分页 + 抽屉详情。
   - 配置页：单列字段账本 + section + sticky 保存栏。
   - 多级详情：右侧抽屉 + 页签 + 固定头部/底部。
   - 运营看板：metrics + 趋势 + 待处理列表。
3. 不允许新造视觉语言、字号、圆角、按钮风格。
4. 新增页面必须复用共享 shell、导航、列表、表单、抽屉、状态组件。
5. 补全后更新页面清单与组件清单，说明与原型的对应关系。
6. 如果后端字段不足，不得伪造数据；先完成可用的 UI 和真实空状态/错误状态，并把缺失字段列为明确的后续项。
7. 如果原型中的页面在生产没有对应功能，不要直接上线空白页；先确认产品意图，能合并的合并，不能合并的按规范补全。

## 7. 技术与组件实现要求

- 使用现有 React + TypeScript 技术栈，不引入新的 UI 框架。
- 抽象共享组件：
  - 用户端：AppShell、Rail/Topbar、Card、Button、Chip、Status、Drawer、MediaDetail、PointsDisplay、AccountMenu、Segment、Filter、EmptyState、Skeleton。
  - 管理端：AdminShell、Sidebar、PageHeader、FilterBand、DataTable、Pager、Drawer、StackedDrawer、FormField、TagInput/MultiSelect、Badge、Metric、EmptyState、ErrorState、Skeleton。
- 不允许每个页面复制一份 Drawer/Table/Form 样式。
- 组件必须接受真实数据和回调，不在组件内部写死 demo 数据。
- CSS 使用项目现有方案（CSS Modules/Tailwind/普通 CSS 均可），但所有值必须来自 token 或原型明确值。
- 图标与字体与原型一致；中文回退到 PingFang SC。
- 图片必须使用真实媒体 URL 或项目现有图片处理链路，不使用 picsum。
- 所有媒体容器使用固定比例/固定舞台，避免布局跳动。
- 所有表格支持空数据、加载、错误、部分失败状态。
- 所有表单支持字段级校验、保存中、保存成功、保存失败。
- 所有抽屉支持键盘操作与焦点管理。
- 所有交互必须尊重 `prefers-reduced-motion`。

## 8. 响应式与质量要求

- 用户端断点：1180 / 980 / 760 / 480。
- 管理端断点：1280 / 1080 / 900 / 640。
- 验收宽度至少覆盖：320 / 360 / 390 / 414 / 768 / 1024 / 1280 / 1440 / 1600 / 1920。
- 任何页面不得出现文档级横向滚动。
- 表格、候选映射、价格表等宽内容必须在自身容器内横向滚动。
- 抽屉在移动端 100vw，内容可滚动，底部操作固定。
- 底部导航与移动端抽屉不能互相遮挡。
- 文字不得被截断成无法阅读；必要的截断必须用 ellipsis 并提供 title 或详情入口。
- 所有交互必须有可见的 focus-visible 样式。
- 颜色对比度满足 WCAG AA；状态不能只靠颜色表达。
- 页面切换、抽屉、Toast 动效使用原型的时长与缓动，不添加炫技动画。

## 9. 数据与 API 集成

- 先盘点现有 API 与类型，不要改接口返回结构。
- 原型中的枚举必须映射到真实枚举值，不允许把中文字符串直接当 API 值。
- 用户/路由/模型等实体映射必须有回退逻辑：缺失时显示原始 ID 并标灰。
- 金额、积分、时长、分辨率、比例等单位必须与后端一致。
- 分页、筛选、排序、搜索必须调用真实查询参数。
- 写操作必须有二次确认、校验、错误提示和刷新策略。
- 禁止在客户端伪造权限；按钮可见性必须与权限一致。
- 若后端暂不支持某功能，使用真实空状态/禁用态，不要用假数据演示。

3. 先输出：
   - 生产页面与原型页面的映射表。
   - 共享组件清单与改造计划。

8. 最终交付 PR 说明，包含：
   - 页面/组件对照表。
   - 关键设计决策。
   - 缺失功能补全说明。
   - 验证命令与结果。
   - 截图或视觉回归结果（桌面 + 移动端）。

## 13. 首次回复格式

在写任何生产代码之前，先回复以下内容：

1. **仓库审计**：现有用户端/管理端路由、页面、组件、API、权限、样式方案。
2. **页面映射表**：原型页面 → 生产路由/组件 → 状态（已有/需改/需新建/需合并）。
3. **组件映射表**：原型组件 → 生产组件 → 复用/新建/替换。
4. **差异与风险**：原型有但生产没有、生产有但原型没有、字段不足、后端不支持的功能。
5. **补全方案**：对缺失页面/功能/交互的具体实现方式，必须引用原型的组件和布局模式。
6. **分阶段计划**：每阶段的文件范围、验证方式、预计交付物。
7. **等待确认**：在计划确认后再开始编码。

开始执行。严格按原型实现，不得遗漏；缺失部分按规范补全，不得另造体系。
