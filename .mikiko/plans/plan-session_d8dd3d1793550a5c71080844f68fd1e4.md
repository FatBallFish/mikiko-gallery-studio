### 1. 创作台与画布的 Seedream 生成方式（第 1、3 项）
- 在模型下方放置“生成方式”字段：**常规生图（默认）／图层拆分**。创作台采用与视频能力切换一致的样式，画布操作台使用下拉框；复用同一模式解析与校验逻辑，移除底部重复入口。
- 常规生图继续按参考图数量自动选择文生图／图生图，不改变原有引用上限。
- 拆层模式将素材标题准确改为“图层拆分来源”，标明必填、仅一张；允许先选择模式再添加来源，缺少来源时禁止估价与提交。数量固定为 1。
- 上传、资产库选择、画布引用、异步上传完成、草稿恢复均遵守单图规则。已有多图切换拆层时保留原图并明确提示处理，不静默删除素材。
- 按实际能力和已确认价格控制拆层可用性，不按型号名称硬编码，也不以零价解锁。切型号、删除唯一来源时保持模式和校验信息准确。

### 2. 画布双击聚焦（第 2 项）
- 复用现有节点边界与视口计算，双击节点后仅更新 viewport 的中心及 zoom，不修改节点位置、尺寸、分组或连线。
- 按画布实际可见区域计算，避开操作台遮挡并保留边距；大节点完整显示，小节点限制最大放大倍数，避免过度放大。缩放限制后重新计算中心。
- 避免双击同时触发图片详情或节点拖动；详情保留明确入口。输入框、编辑区域、操作按钮、连接端口和缩放手柄保留自己的交互，空白双击菜单不受影响。

### 3. 资产公开区域与筛选（第 4—7 项）
- 抽取图片／视频共用的公开状态、操作、说明和错误展示，分别连接各自现有公开接口。保留申请、待审核、拒绝、已公开、撤回的真实生命周期。
- 图片在卡片上直接查看和操作公开状态；现有不支持公开的图片来源明确显示原因，不提供无效按钮。
- 分组从尺寸属性中移出，以 tag 显示在公开状态之后；没有公开能力的其他媒体也保留分组展示。
- 视频属性改为“像素 · 格式 · 时长”，复用统一时长格式化，正确处理缺失及异常元数据。
- 增加独立的“公开状态”筛选，贯穿前端、HTTP、服务、仓储和 OpenAPI，在服务端分页之前生效；统一新旧图片和视频状态别名，不与处理状态混用。

### 4. 公开广场视频互动（第 10 项）
- 视频卡片补齐右上角点赞、收藏、下载操作，与图片使用一致的 hover、键盘 focus 和触屏展示规则，操作不触发播放或详情。
- 补齐真实视频互动存储、幂等接口、计数和当前用户状态，并更新混合 Feed 的热度排序、已点赞／已收藏筛选，避免只加按钮而数据链路缺失。
- 下载沿用已审核公开视频授权边界，补齐附件文件名及下载语义；撤回后不能继续通过公开接口获取内容。匿名互动提供登录引导。

### 5. 全站视觉与反馈一致性（第 11—14 项）
- 资产、广场、首页、图片／视频创作历史的媒体名称统一固定两行高度，两行截断，单行文字顶对齐；清理移动端取消高度的覆盖规则。
- 以创作页实际 topbar 的高度、内边距为基准统一用户端 Shell，逐页测量路由差异。画布专用工具栏保留其功能结构，同时对齐共用顶部规格，避免误把创作模式切换栏当作全站 topbar。
- 重构 Toast 为符合现有视觉体系的 Success、Warn、Error、Info 四等级，统一图标、颜色、边框、间距、关闭和辅助技术播报；核查用户端和管理端实际 Toast 入口与调用，按真实语义分类。修正重渲染导致计时重置的问题，避免把“任务已提交”描述成“生成完成”。
- 首页最近任务完成时采用**100% 静止进度条**，移除完成态扫动动画，保留组件高度及与左侧区域的布局；恢复中、失败和无结果状态保留真实语义。

### 6. API Key／MCP 完整接入与设置页（第 8、9 项）
- 对照实际路由、共享操作目录和 OpenAPI 建立完整清单，补齐所有对外接口的 BaseURL、认证、scope、请求／响应字段、约束、分页、异步任务、幂等、报价、上传下载和错误码。错误清单覆盖 REST、OAuth 与 MCP 各自结构，说明触发条件、是否可重试及处理方式，避免仅列通用字符串。
- 统一文档站、Markdown 指南和 OpenAPI 的内容来源与一致性检查；提供可运行的最小接入示例及完整任务生命周期示例。
- API 密钥页展示并支持复制：服务根地址、原生 REST BaseURL、OpenAI BaseURL、MCP URL。端点来自明确的运行配置；未配置时显示原因，不复制假域名或凭空推导 OAuth issuer。
- 提供 Mikiko／ZCode、Codex、Claude 的客户端适用配置与操作说明。JSON 客户端给 JSON，使用 TOML 或 CLI 的客户端提供其实际格式和安装方式，不伪造通用 JSON。模板不包含用户 Secret 或浏览器 token。
- 明确解释 MCP token 获取流程：客户端请求 MCP 后，通过 401 challenge、受保护资源 metadata、OAuth discovery、客户端注册、PKCE、浏览器登录／同意、回调和 token 交换获得凭据；用户无需手工抓取浏览器 token。
- 逐段核验公开网关实际路由、响应类型、WWW-Authenticate、授权跳转、资源 audience、Origin 和流式连接。修复确认的协议兼容及注册限流问题，保留 PKCE、redirect、scope、resource 和 HTTPS 安全校验。
- “已连接应用”及同意页区分未配置、未登录、真正过期、网络错误、服务端错误和空列表，提供适当重试及撤权反馈，不再统一误报。
- **生产前提与边界**：当前生产没有 Gallery 的 canonical HTTPS 地址，旧域名属于同机其他系统。代码和文档会提供清晰的未配置状态、部署校验及合法配置路径；不会复用其他系统域名、伪造 issuer 或修改绑定摘要来开启 OAuth。若需要让生产 MCP 真正可用，必须落实 Gallery 所属 HTTPS 入口及受支持的配置更新。无法从已授权配置确定的域名选择会明确列为部署阻塞，不宣称只改文档就解决 ZCode 授权。
