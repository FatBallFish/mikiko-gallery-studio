# API 统一重构与标准 MCP 服务实施方案

## 已确认的决定

- **开放 API 统一使用 `Authorization: Bearer <API_KEY>`，取消请求签名。** 不再要求 `X-Signature`、时间戳和请求体哈希鉴权。
- **直接替换旧开放接口**，不维护旧 HMAC 接口兼容层。同步更新调用示例、API 密钥页面和文档。
- MCP 使用用户通过 **Mikiko Studio 浏览器 OAuth 授权**获得的独立访问令牌。
- 网页用户会话、管理员鉴权、厂商回调和支付 Webhook 是不同的信任边界，保留各自正确的鉴权方式，不改为普通 API Key。
- 保留工作区里前几轮尚未提交的功能与修复。本次不自动提交、推送或发布。

## 1. 先交付准确的功能与接口盘点

新增功能清单、现有接口对照、新接口目录及变更说明，覆盖：

- 用户身份、余额、积分预留与结算、API Key 配额。
- 图片／视频模型能力、参数校验、估价、任务创建、进度、结果、失败与重试。
- 资产、上传、派生处理、临时访问、项目、资产分组。
- 已有历史、公开审核、画布、管理与部署能力，说明它们是否属于本次对外 API／MCP 范围。

本次完整开放你列出的能力。画布编辑、支付购买、平台管理和公开审核不自动变成 MCP 工具，避免把“盘点已有功能”扩大为开放全部后台权限。

## 2. 架构：一套业务操作，三种入口

建立共享的开放能力应用层：

`API Key REST / OpenAI 兼容 / OAuth MCP → 统一业务操作 → 现有服务与存储`

共享层负责身份上下文、权限、项目与资产归属、能力验证、报价、配额、幂等和审计。MCP 不伪造网页 JWT，也不通过内部 HTTP 回调网页接口。

统一身份上下文包含用户、API Key 或 OAuth 客户端／授权、权限范围及计费来源。调用者不能通过请求参数指定任意用户身份。

## 3. 新开放 API 契约

建议使用统一 `/api/open/v1`，OpenAI 保持标准 `/v1`。资源名和方法在实施前写入 OpenAPI 并由测试锁定。

| 能力 | 新接口族 |
|---|---|
| 当前身份与余额 | `GET /api/open/v1/me`、`GET /me/balance` |
| 图片模型 | `GET /api/open/v1/image-models` |
| 图片完整预校验 | `POST /api/open/v1/image-tasks/preflight` |
| 图片任务 | `POST/GET /api/open/v1/image-tasks`、`GET /image-tasks/{id}` |
| 图片任务进度 | `GET /image-tasks/{id}/events` |
| 视频模型 | `GET /api/open/v1/video-models` |
| 视频完整预校验 | `POST /api/open/v1/video-tasks/preflight` |
| 视频任务 | `POST/GET /api/open/v1/video-tasks`、`GET /video-tasks/{id}` |
| 视频进度／取消 | `GET /video-tasks/{id}/events`、`POST /video-tasks/{id}/cancel` |
| 资产 CRUD | `GET /assets`、`GET/PATCH/DELETE /assets/{id}`；创建通过上传或生成入库完成 |
| 资产临时访问 | `POST /assets/{id}/access`，按 preview、download、poster 等用途返回链接及有效期 |
| 上传资源到资产库 | `/uploads` 初始化、状态、分片目标／代理分片、完成和取消 |
| 分组 CRUD | `GET/POST /groups`、`GET/PATCH/DELETE /groups/{id}` |
| 项目 CRUD | `GET/POST /projects`、`GET/PATCH/DELETE /projects/{id}` |

统一分页、筛选、错误码、请求 ID、时间格式、版本冲突及幂等规则。积分保持五位小数字符串，不用浮点数表示资金。

删除资产与删除历史记录继续分离；项目删除沿用默认项目保护和非空项目转移规则。

### 完整预校验

图片预校验将补齐当前“只按参数和参考图数量估价”的缺口。图片和视频都使用完整请求验证：

- 用户和项目归属、模型可见性及当前能力。
- 真实参考资产、状态、媒体类型、输入角色及数量。
- 提示词模板、变量和资源绑定。
- 尺寸、质量、数量、时长、声音等组合合法性。
- 预计扣费、最大预留、余额及 Key 配额是否足够。

返回规范参数、字段错误／提示、报价有效期、能力版本及报价凭证。预校验不扣费；创建仍重新校验，并在一次业务流程中原子预留配额／积分。过期或不匹配报价明确拒绝，不能靠预校验绕过创建检查。

异步任务返回稳定任务 ID、阶段、错误、结果资产 ID 和可续取的访问方式，不把短期 URL 当作资产身份。

## 4. API Key 改造

- 复用已有 Bearer Key 哈希认证、停用、过期、用户状态、限速和积分配额。
- 取消旧签名认证入口及开发者签名示例，清理不再需要的签名专用秘密读取逻辑；不要误删其他用途的加密配置。
- 增加明确操作权限，例如 `profile:read`、`balance:read`、`models:read`、`generation:read/write`、`assets:read/write/delete`、`groups:read/write`、`projects:read/write`。
- 用户可为新 Key 选择权限；迁移已有 Key 时保留原有生图能力，不自动授予资产删除、项目写入等新增权限。
- 保持 Key 模型分组、RPM、总额度、日额度的现有约束，并补齐视频调用的 Key 归因与配额扣减／退回，不能只在图片路径限制。
- 每个请求都校验 Key 与当前用户状态；生成幂等重放不重复扣费。

## 5. OpenAI 兼容接口

保留并整理：

- `GET /v1/models`
- `POST /v1/images/generations`
- `POST /v1/images/edits`

标准 OpenAI SDK 可直接用 Bearer Key 调用。

- 默认同步返回 OpenAI 兼容响应；内部使用同一任务与计费链路。
- 原生异步调用使用统一任务接口。
- `stream=true` 采用明确文档化的 SSE 事件协议，支持生命周期／结果流；真正的部分图片事件只在选中路由及上游具备能力时开放，不能把“等待中的心跳”称为部分图片生成。
- 对不支持的流式／部分图片参数返回明确错误。文档区分标准 OpenAI 事件与平台扩展，不在兼容路径中伪装不兼容的 `202` 任务响应。
- 同步或流式连接断开不丢失已提交的持久任务；超时、任务可查询性和计费结果有清晰契约。

## 6. 分组成为真正可管理的资源

当前分组是单个 `group_name` 字符串，没有空分组、稳定 ID 或独立生命周期。为满足完整 CRUD：

- 新增用户／项目下的资产分组实体，包含 ID、名称、版本和时间。
- 每个资产仍是单分组，增加可空 `group_id`。
- 从现有 `(用户、项目、group_name)` 回填，保留已有分组显示和资源归属。
- 分组删除仅解除归组，不删除资产。
- 项目间转移资产时，在目标项目按名称解析／创建对应分组，保持当前页面体验；默认未分组仍可使用。
- 同步适配现有网页分组选择和上传赋组，避免开放 API 与网页形成两种分组真相。

## 7. MCP 服务与工具

使用官方 Go MCP SDK，挂载同一 API 进程的 `/mcp`，采用 **Streamable HTTP**。实施时固定 SDK 版本与协议版本，按当前官方规范提供版本协商，并测试其支持的常用旧版本，不能笼统宣称兼容所有客户端。

工具与统一业务能力对应，例如：

- `get_current_user`、`get_balance`
- `list_image_models`、`preflight_image_task`、`create_image_task`、`get_image_task`、`list_image_tasks`
- 视频对应工具及取消工具
- `list/get/update/delete_asset`、`get_asset_access`
- `list/create/get/update/delete_group`
- `list/create/get/update/delete_project`
- `create_upload`、`get_upload`、`get_upload_part_url`、`complete_upload`、`abort_upload`

生成工具优先返回异步任务 ID；查询结果返回结构化资产及临时链接，不让模型长时间等待，也不把大视频塞进 JSON 上下文。上传使用既有分片／预签名机制，MCP 返回上传目标，客户端传输字节；不提供可任意抓取内网 URL 的导入工具。

工具提供输入／输出 JSON Schema、明确错误和效果注解。只读、花费积分、删除分别授权；工具列表过滤不能代替每次调用的权限检查。

## 8. Studio OAuth 授权

现有 OIDC 是 Studio 登录到外部提供商的客户端，不能直接替代 MCP 授权服务器。新增 Studio 管理的 OAuth 授权层，复用现有登录界面建立用户身份。

- 浏览器授权码流程＋PKCE S256，精确 redirect URI，短时单次 code，绑定 client、scope、用户和 MCP resource。
- 授权页展示客户端、权限和生成扣费能力，用户可以同意或拒绝。
- 提供 RFC 9728 资源元数据、授权服务器发现、token、refresh、revocation 和客户端注册机制。
- 按当前 MCP 规范优先支持 Client ID Metadata Documents，并提供受限动态注册以兼容常见客户端；远程元数据读取需 HTTPS、公网地址校验、大小／超时限制和安全缓存。也支持预注册客户端。
- MCP access token 与网页 JWT／API Key 分离，绑定 issuer、audience、client、grant、scope；刷新令牌轮换并检测重放。撤销后每次工具调用即失效。
- “登录”由 MCP 客户端触发浏览器授权，不设计传密码的登录工具；“登出”通过撤销当前应用授权实现，不自动退出所有 Studio 浏览器会话。
- 用户设置增加“已连接应用”，可查看和撤销授权。
- 修复已发现的 OIDC-only 用户会话刷新限制，使无本地密码的正常 OIDC 用户能够持续使用 Studio 登录授权流程。

## 9. 网关、配置和文档

- Go 网关、Nginx、容器及原生部署正确路由 `/api/open/v1`、`/v1`、`/mcp`、OAuth 和 `.well-known`。
- SSE 关闭代理缓冲，合理心跳、超时和取消；MCP 明确验证 Origin。
- issuer/resource 从已验证的公开 URL 配置构造，生产使用 HTTPS；仅本地开发允许 loopback HTTP，不信任任意 Host／Forwarded 头生成授权地址。
- OpenAPI 为 REST 唯一契约来源，修正文档站目前只提取旧前缀的构建脚本。
- 更新开发者文档、API Key 页面、curl/Python/JavaScript 示例、上传示例、OpenAI SDK 示例、错误码／计费／幂等说明。
- 新增 MCP 接入、OAuth 登录／撤销、权限、工具清单和常见客户端配置说明；提供可运行示例及旧开放接口迁移表。
- 删除旧 HMAC 用户接口文档与代码示例；保留并正确分类厂商回调／Webhook 文档。

## 10. 实施顺序与验收

按依赖连续推进，不以只完成文档或部分端点作为交付：

1. 保存本次需求、功能盘点、接口设计和能力／权限矩阵，建立对应 coding context。
2. 共享应用操作与 Bearer API Key、统一预校验／报价及视频配额。
3. 项目、真实分组、资产上传和临时访问接口；替换旧开放路由。
4. OpenAI 同步／流式适配和文档。
5. OAuth 持久授权、同意页、客户端接入与撤销。
6. MCP transport、完整工具集和权限映射。
7. 文档、SDK 示例、部署与全链路验收。

验证包括：

- API Key 生命周期、权限、跨用户资产／项目、图片视频配额和幂等计费。
- 预校验与创建一致性、报价过期、参数变更及参考资源状态变化。
- 分组回填、空分组、重命名、删除不删资产、跨项目转移。
- OpenAI SDK 请求响应、流式事件、断线和持久任务。
- OAuth PKCE、code 重放、redirect/audience/scope 错误、刷新并发与撤销。
- 官方 MCP SDK 客户端／Inspector 协议测试、工具 schema、权限不足和任务全流程。
- 上传校验／恢复、临时 URL 到期与范围读取。
- 全量仓库验证、独立代码审查、隔离 API/MCP 冒烟以及本地授权界面验收。

测试使用隔离假上游，不自动发起真实收费生成，不向外发布内容。数据库变更先做迁移回归和本地备份；部署本身不在本次自动执行范围。
