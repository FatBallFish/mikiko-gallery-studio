# DevOps Packaging

This directory contains templates copied into `target/devops/*` by
`scripts/devops/package.sh`.

Build targets:

```bash
scripts/devops/package.sh user-web
scripts/devops/package.sh admin-web
scripts/devops/package.sh api-server
scripts/devops/package.sh worker
scripts/devops/package.sh all
```

Backend packages use `APP_ENV` to select the runtime config file at build time:

```bash
APP_ENV=dev scripts/devops/package.sh api-server
APP_ENV=pro scripts/devops/package.sh worker
APP_ENV=pro scripts/devops/package.sh all
```

`APP_ENV=prod` and `APP_ENV=production` are accepted aliases for `APP_ENV=pro`.
The selected `configs/config.<APP_ENV>.yaml` file is copied into each backend
artifact as `config.yaml`.

Target layout:

```text
target/devops/user-web/
  dist/
  env/frontend.env.example
  env.template.js
  nginx.conf
  start-user-web.sh

target/devops/admin-web/
  dist/
  env/frontend.env.example
  env.template.js
  nginx.conf
  start-admin-web.sh

target/devops/api-server/
  bin/pic-gallery-api
  config.yaml
  api/openapi/
  run-api-server.sh

target/devops/worker/
  bin/pic-gallery-worker
  config.yaml
  run-worker.sh
```

Runtime config:

- Frontends read `dist/env.js`, generated by `start-user-web.sh` or
  `start-admin-web.sh` from `PIC_GALLERY_API_BASE_URL`.
- Backend services read `config.yaml` from the artifact directory. Runtime
  database, Redis, BFSS/object storage, provider, SMTP, security, and worker
  settings should be edited in that file before packaging or before starting the
  service on the server.
- `run-api-server.sh` installs or updates `pic-gallery-api.service`, then runs
  `systemctl daemon-reload`, `systemctl enable`, and `systemctl restart`.
- `run-worker.sh` installs or updates `pic-gallery-worker.service`, then runs
  `systemctl daemon-reload`, `systemctl enable`, and `systemctl restart`.
- The service names can be changed with `PIC_GALLERY_API_SERVICE_NAME` and
  `PIC_GALLERY_WORKER_SERVICE_NAME` when running the scripts.
- Cluster deployments should use PostgreSQL, Redis, and either a shared local
  storage volume or S3-compatible object storage.
